## Поворот вектора на заданный угол

Модуль поворота составлен следующими файлами:

```
├── Cordic
│   ├── cordic.m
│   ├── cordic_vector_rotator.sv
│   ├── cordic_vector_top.sv
```

### cordic.m

Матлабовский файл для поэтапного вычисления поворота вектора без всяких двоичных прелестей (типа преобразования углов из радиан
в отсчеты и т.д.). Использовался только во время разработки, для нормальной работы модуля не требуется.

### cordic_vector_rotator.sv

Модуль, который осуществляет поворот вектора на заданный угол. Это всего лишь одна итерация из множества итераций последовательных
приближений.
На вход попадает величина угла **rot_angle** на который будет осуществлен сдвиг,
данный угол вычисляется вышестоящим модулем (об этом далее) и является константным для каждой из итераций.  
**x_i**, **y_i** - значения координат вектора для поворота;  
**angle_i** - текущий угол, на который был повернут вектор в предыдущей итерации;  
**quarter_i** - четверть на окружности, в которую требуется повернуть изначальный вектор.
данное значение иранзитом пробрасывается через модуль.  
**valid_i** - сигнал валидности данных для поворота. Через модуль пробрасывается транзитом;  
Модуль задерживает данные только на один такт.  
**user_i** - пользовательский сигнал для транзитной передачи через модуль (актуален только с установленным сигналом **valid_i**).

### cordic_vector_top.sv

Собственно сам модуль верхнего уровня поворота вектора на требуемый угол. Модуль
осуществляет поворот только против часовой стрелки на углы в диапазоне $[0;2\pi)$.

<u>Параметры модуля</u>:  
*XY_WIDTH* - разрядность шин координат вектора $(x_i; y_i)$;  
*ANGLE_WIDTH* - разрядность угла поворота;  
*ROUND_TYPE* - тип округления после умножения выходного результата на коэффициент деформации;  

<u>Входные порты</u>:  
**x_i**, **y_i** - начальные значения координат вектора для поворота;  
**angle_i** - значение угла, на который необходимо повернуть вектор;  
**valid_in** - сигнал валидности входных данных для поворота.  
**user_i** - пользовательский сигнал для транзитной передачи через модуль (актуален только с установленным сигналом **valid_i**).

<u>Выходные порты</u>:  
**x_o**, **y_o** - вычисленные значения координат вектора после поворота;  
**valid_o** - сигнал валидности выходных данных после поворота.  
**user_o** - пользовательский сигнал после транзитной передачи через модуль (актуален только с установленным сигналом **valid_o**).  
**sat_flag_o** - сигнал символизирует о наличии переполнения при суммировании/вычитании в одном из каскадов поворота.
Необходимо выполнить проверку амплитуды значений координат векторов, которые подаются на вход модуля. 

<u>Преобразование углов</u>:  
Все операции с тригонометрическими функциями выполняются в области радиан.
Поскольку диапазон углов поворота $[0;2\pi)$, то на единицу угла на порту **angle_i** приходится
$\frac{2\pi}{2^{ANGLE\_WIDTH}}$ радиан, и, соответственно, один радиан составляет $\frac{2^{ANGLE\_WIDTH}}{2\pi}$ отсчетов.
Таким образом величина угла поворота на порту **angle_i** вычисляется как:  
$angle\_i = \frac{2^{ANGLE\_WIDTH}}{2\pi}\phi$,  
где $\phi$ - угол поворота в радианах.  

Поворот вектора целесообразно выполнять только в первом квадранте для $[0;\pi/2)$, т.к. значения
поворотов для углов в остальных квадрантах могут быть легко получены при помощи упрощения классическими
тригонометрическими выражениями. Таким образом из величины входного угла поворота **angle_i**
определяется квадрант в котором этот угол находится (старшие два бита) и далее угол отправляется на
модули поворота с обнуленными старшими битами (т.е. с диапазоном углов $[0;\pi/2)$).
Пусть $phi$ - угол поворота, а $phi^*$ - угол поворота в диапазоне $[0;\pi/2)$, тогда:  
I квадрант:  
$x_o = x_icos(\phi)-y_isin(\phi) = x_icos(\phi^*)-y_isin(\phi^*) = x_o^*$  
$y_o = y_icos(\phi)+x_isin(\phi) = y_icos(\phi^*)+x_isin(\phi^*) = y_o^*$  
II квадрант:  
$x_o = x_icos(\phi)-y_isin(\phi) = x_icos(\frac{\pi}{2}+\phi^*)-y_isin(\frac{\pi}{2}+\phi^*) = -y_o^*$  
$y_o = y_icos(\phi)+x_isin(\phi) = y_icos(\frac{\pi}{2}+\phi^*)+x_isin(\frac{\pi}{2}+\phi^*) = x_o^*$  
III квадрант:  
$x_o = x_icos(\phi)-y_isin(\phi) = x_icos(\pi+\phi^*)-y_isin(\pi+\phi^*) = -x_o^*$  
$y_o = y_icos(\phi)+x_isin(\phi) = y_icos(\pi+\phi^*)+x_isin(\pi+\phi^*) = -y_o^*$  
IV квадрант:  
$x_o = x_icos(\phi)-y_isin(\phi) = x_icos(\frac{3\pi}{2}+\phi^*)-y_isin(\frac{3\pi}{2}+\phi^*) = y_o^*$  
$y_o = y_icos(\phi)+x_isin(\phi) = y_icos(\frac{3\pi}{2}+\phi^*)+x_isin(\frac{3\pi}{2}+\phi^*) = -x_o^*$  

Углы поворота для каждой итерации вычисляются согласно общепринятым выражениями $angle_i = atan(2^{-i})$,
затем они преобразуются в соответствие с вышеприведенными выражениями перехода от радианов к отсчетам:  
$rot\_angle_i = \frac{atan(2^{-i})}{2\pi}2^{ANGLE\_WIDTH}$.

### cordic_vector_top_tb.sv

Модуль для проверки работоспособности **cordic_vector_top.sv**. Проверка достаточно
примитивна. Проводится генерация *total_vectors* векторов с произвольными координатами
и углами поворота. Для них вычисляются координаты после поворота при помощи
вышеприведенной классической математической формулы и сравниваются с результатами,
которые получены из модуля **cordic_vector_top.sv**. Если абсолютное отклонение
результатов превышает значение *tol*, то фиксируется ошибка и сообщение печатается
в консоль.

<u>Замечания по поводу диапазонов входных значений.</u>.  
Поскольку при повороте вектор не изменяет своей амплитуды (абсолютного значения), то могут возникнуть некоторые прелести
при повороте. Допустим мы взяли вектор с максимальными значениями для координат (x, y), которые может принять модуль и
хотим повернуть его на, скажем, 45 градусов. Получится, что вектор после поворота выйдет за пределы допустимой сетки дискретных
значений. Поэтому важное правило - не подавать на модуль значения векторов, амплитуда которых превышает максимальное значение,
которое можно подать на одну из координат. При этом также необходимо учитывать возможные переполнения при суммировании
внутри каждой итерации.
